# Release notes — v1.20.0

> **Audience:** adopters running brain-stem, and anyone evaluating it. This page explains, in plain language, what this release changes, who it affects, and what to do. No prior technical background is assumed; every term is explained the first time it appears.

**v1.20.0 is a minor release that ships one automatic upgrade-time migration.** A migration is a self-contained, idempotent step that runs during a normal upgrade and converges your existing installation to the new state; you do not run it by hand, and running it twice changes nothing the second time. This one, `0013-inbox-deferred-converge`, rewrites inbox notes you left marked `DEFERRED`, and this page says what it touches and what it never does. Six threads: **tools to extend and inspect your system**, **a stricter idea funnel**, **conveniences that last across upgrades**, **advisory hooks that no longer skip your permission prompt**, **shipped text that says what the code does**, and **identity stamping for your work folder**.

---

## Extend and inspect your system

- **An extension seam that survives upgrades.** `capability-registry-parity.sh --root <dir>` audits a capability root of your own (a skill folder under a name no shipped skill uses, holding its registry, `SKILL.md` headings and `capabilities/*.sh`) instead of the shipped one. The installer copies skills from a named list, so a skill folder of your own is never copied over.
- **Two new frontmatter checks.** `skill-parity` now reports `skill-parity-unknown-frontmatter-key`, a `SKILL.md` frontmatter key Claude Code does not recognize (it would be ignored without an error), and `skill-parity-listing-length`, a skill whose `description` plus `when_to_use` passes the 1,536-character listing limit.
- **A map of what your system runs.** `/librarian system-map` (`system-map.sh [--render | --check | --dry-run] [--out DIR]`) reads the installed home and writes one six-line page per hook, librarian capability, skill and scheduled job, plus an index. A capability, skill or hook of your own appears on the next render, and `--check` reports a page that has gone stale.

## The idea funnel

- **Graduation needs triage.** `promote-from-inbox.sh` checks a note's status before it graduates: only `triaged` or `briefed` passes (the key `inbox.graduation_precondition` in the plans governance file), for the lead note and for every `--absorb` note. An untriaged note is refused with the triage command to run, so after an upgrade your untriaged inbox notes need `/backlog-triage` before they graduate. No migration is involved. An ABSORB target whose plan is already finished is refused.
- **Smaller funnel fixes.** `triage-apply.sh` creates a missing `## Notes` section instead of refusing, and `rehome-stray.sh --mint` triages the note it mints.
- **A new command to re-decide a note.** `skills/backlog-triage/scripts/redecide-idea.sh <inbox-slug> (--disposition <value> [class flags] | --clear) --rationale "<one line>"` replaces, or with `--clear` removes, the decided disposition of one flat idea note, and records a dated `REDECIDE` line under its `## Notes`. A settled, graduated or already-targeted note, and an ABSORB target whose plan is finished, are refused with a pinned reason. A cleared note can then be taken by `promote-from-inbox.sh <lead> --absorb <slug>`.
- **Inbox notes still marked DEFERRED.** The upgrade now converges them. Migration `0013-inbox-deferred-converge` rewrites `disposition: DEFERRED` on each flat idea note in `_inbox/` to `NO-BUILD`, adds `reopen_gate: manual` when the note names no gate, and appends one line under the note's `## Notes`. The prior bytes of each rewritten note stay in `_inbox/` as `<slug>.md.pre-0013`, a recovery copy that nothing reads. Notes already settled under `_inbox/_settled/`, and any note that carries `absorbed_into`, `promoted_to` or `resolution`, are never touched. The next `/librarian backlog-index` run parks each converted note whose gate is registered, `manual` among them, under `_inbox/_settled/`, as it does any NO-BUILD note. To take one up again, run `skills/backlog-triage/scripts/reopen-idea.sh <slug>`, then decide it with `skills/backlog-triage/scripts/redecide-idea.sh <slug> --disposition <value> --rationale "<one line>"`. This replaces the v1.19.0 instruction to open each such note and edit it by hand.

## Conveniences that last

- **Durable hook opt-out.** `field-set.sh settings hook off <hook>` on a foundation-required hook now records the hook in the user manifest's `hooks.disabled` list, and the installer's required-hook reconciler leaves every listed hook out of `settings.json` on each upgrade. `hook on` removes it from the list. The `hook off` statement in the configuration guide is extended to match: a foundation-required hook you turn off stays off across upgrades.
- **The active-plan verb.** `skills/new-plan/lib/active-plan.sh set <plan> [<sub-plan>|.] [--project <spoke>]` points a spoke at its active plan and stamps a planned or paused plan in-progress; it refuses a completed or superseded plan. `active-plan.sh clear` removes the pointer.
- **Capture warning.** A capture run from inside the plans root without `--project` now warns that the note resolved to the `home` spoke and names the flag that files it under its owning spoke. The capture itself is unchanged.
- **`plan-rule --body-file`.** A spec-change ruling can supply its own Context, Decision and Consequences sections from a markdown file; a section the file omits keeps the generated text.
- **`reopen-idea --force`.** A parked idea behind a command gate can be re-opened by hand. The gate must still be registered, and it is not evaluated.
- **`rehome-stray --discard --reason <text>`.** A plans-root stray with no owning plan can be moved aside to the state root's `discarded-strays/` directory, with its reason logged.
- **`library-scrub --enqueue <plan>`.** A completed plan outside the promotion queue can be queued for triage straight from the census.
- **Pinned `reshaped_memory`.** A promotion item can carry the memory file it proposes; `review.sh confirm` writes that file when no `--written` file is named, after checking its shape.
- **Rollup after `--add-subplan`.** Adding a sub-plan now refreshes the master plan's sub-plan table in the same run; if the refresh fails, the run still succeeds and prints the one command that refreshes it.
- **Command in place of a typed loop.** `installer/render-launchd.sh --all` renders both shipped launchd jobs (writer-reconciler, doc-amender) in one command, and also takes `--staging-dir <dir>` and `--dry-run`. The install epilogue prints it in place of the typed per-job loop.
- **Amender conflicts.** `skills/doc-amender/process.sh --list-conflicts` lists pending `*.amender-conflict.json` sidecars. `--resolve <sidecar>` moves a triaged one to `<writer dir>/_resolved/`, where it is kept, never deleted. The operator's edit still wins, and there is no destination merge.
- **claude-mem context recipe.** `skills/onboarder/scripts/claude-mem-context-set.sh` applies the claude-mem context recipe to `~/.claude-mem/settings.json`. It runs as a dry run by default and writes only under `--apply`. The README's optional claude-mem section points to it.
- **Drift allowlist.** `hooks/lib/field-set.sh drift-allowlist add <capability> --reason <text>` records a `provides_overlap` exemption in the drift allowlist (`hooks/drift-allowlist.json`). The schema now requires `capability`.
- **`dispatch.sh --overnight` is refused.** No command ran the queued runs it created. It now exits 2 before any side effect and points to `--delay`. A queue file an earlier release wrote is kept, and `--hold`, `--unhold` and `--queue-status` still work over it; hold and unhold act on entries an earlier release queued, and nothing new is queued.

## Advisory hooks no longer skip the permission prompt

An advisory from `hooks/pre-write-guard.sh` or `hooks/pre-asq-guard.sh` now carries the note only. It used to carry `permissionDecision: "allow"` as well, and Claude Code reads that key as an approval, so the call ran without its permission prompt. An advisory note on a write therefore switched the prompt off for that write.

- **What you will see.** A write that draws an advisory now goes through your normal permission flow, so you can see a prompt where none appeared before. A path where the guard has nothing to say prints nothing. Denies are unchanged, and every advisory keeps its wording: "this write is allowed" means the hook does not block the write, and your permission settings still decide it.
- **The count.** The fix covers 18 `PreToolUse` call sites in `pre-write-guard.sh` and 1 in `pre-asq-guard.sh`.
- **Size bound.** The note-only output carries the same soft size bound the approving form carried, so a long advisory is trimmed the same way.

## Library promotion uses your own Claude Code login

- **The triage call signs in with your login.** With library promotion switched on, the call that judges a completed plan's research now runs `claude --safe-mode -p --model haiku` with your own Claude Code login. It used to run `claude --bare -p --model haiku`, and `--bare` skips the OAuth and keychain login. On a machine signed in with a Claude subscription and no API key, every triage call therefore failed with "Not logged in", and the plan stayed pending with a failure reason. Safe mode keeps the login and loads none of your hooks, plugins, MCP servers, CLAUDE.md files or auto memory. The call also passes `--settings` that switch off hooks, claude.ai plugin sync and auto memory, and it writes no session.
- **Prompt mode never answers for you.** With library promotion in `prompt` mode, a Stop asks about one ready plan and never answers a second one; only `auto` mode answers without asking, and `library-scrub.sh --claim-answer` claims nothing in any other mode.
- **Switching it back on never offers a plan completed while it was off.** `--mode set off` now drops the recorded baseline, so each later switch-on, by command or by editing the manifest, records the plans already completed afresh and never offers them. The triage call skips a research file whose resolved path leaves the plan folder (a symlink, for example); when every research file is outside it, the call is not made and the plan is recorded as a skip. Answering yes blocks such a file instead of copying it. The one-time off notice is neither shown nor marked used in a headless session. `SECURITY.md` now says the detached run makes one call per plan awaiting triage, that `--answer <plan> always` also turns `auto` on, and that `--enqueue` is the one exception.
- **Texts.** The librarian skill's `--triage` description and the Library promotion paragraph of `SECURITY.md` describe the call this way.
- **Version floor.** `--safe-mode` first shipped in Claude Code 2.1.169. On an older CLI the triage call exits 1, and the queue reason names the unknown option.
- **After you upgrade.** A plan whose triage already failed stays pending with its old reason. Run `library-scrub.sh --triage <plan>` for each one that `library-scrub.sh --pending` lists.

## Identity fields on project files, at write time

- **Write-time Work stamping.** The universal identity stamp (`created`, `id`, `schema_version`, `description`) now fires when Claude Code writes a Markdown file at its physical project path under your work root (`$WORK_HOME`), not only when it writes the same file through the vault's `Work/` view. The `id` is the one the `Work/<path>` spelling would give, so a file has one identity whichever way it was written. Paths inside a `.claude/` folder and folders that carry a `.no-spoke` marker are skipped, and only the first folder below the work root decides the `.no-spoke` skip.
- **Generated indexes are no longer reported as missing fields.** `frontmatter-enforce --check` now reads each capability's declared `writes[]` and `generated_exemption` from the capability registry. A field that a declared writer deliberately leaves out of an index it owns is no longer reported. The work-index writer declares the `deliverables/` and `reference/` indexes of each project, so those drop out of the findings. If the registry cannot be read, the check reports everything, as before.
- **The fixer only inserts.** `frontmatter-enforce --fix` adds missing keys and never rewrites a key you already have. A flow-style list such as `tags: ["#project/x"]`, a comment line and a quoted description keep their exact bytes through a backfill.
- **Corrected texts.** The write guard's cohort advisory now points at the manual backfill (`frontmatter-enforce --fix`) instead of promising an automatic one. The mandatory-files rule for `_index.md` now says that the cohort is stamped at write time on the physical work-root path too, that the audit is `--check` only, and that files that already exist take the manual backfill.

## Cleaner shipped text and honest help

- **Shipped text.** The foundation no longer carries the leftover punctuation a stripped build reference used to leave in comments, templates and messages. The cleaner gains two rules: it drops an emptied `()` and a stripped `(per)` frame. A shell function definition and `return ()` are left alone.
- **Reproducible stamps.** `built_at`, `generated_at` and the per-pillar times in `governance/foundation-master.json` and `governance/foundation-manifest.json` now come from one source: `SOURCE_DATE_EPOCH` when the caller sets it, otherwise the dev commit's own time. The same commit stamps the same bytes.
- **Help output.** Every script's `--help` prints its leading comment block, found by reading the file. It used to print a fixed line range, which could slide onto code after the cleaner shortened a header. No `--help` prints a code line now, and some print more of their header than before.
- **Release sweep.** The residual sweep gains a husk arm: it scans for the pinned husk shapes in text that differs from the published base and exits 1 on a hit.
- **Kept keys.** Twenty-three documentation keys in the governance JSON now ship instead of being stripped, so an adopter reading a rules file sees the note that explains it. No runtime reader consumes them.
- **Silent failures reported.** `hooks/lib/review-queue.sh` prints one stderr line when `jsonschema` cannot be imported; the item is still enqueued. `session-register.sh` and `session-deregister.sh` name the return code in their skip line and say lock contention only for rc 75.
- **Work-spoke advisory.** The `[WORK SPOKE]` advisory says the write is allowed and no longer fires on a dot-prefixed first segment such as `.git`.

## What else changed

- **Plan tooling.** Flat and master mints (`skills/new-plan/new-plan.sh`) stamp `disposition: STANDALONE`. The three `sub_plans[].slug` seed sites (`--add-subplan`, the master template, `graduate-plan.sh`) write the directory form `NN-slug`, the same form the aggregator writes. Outside `--check`, `subplan-aggregate` takes an exclusive lock on the master directory before it reads the master; `SUBPLAN_AGGREGATE_LOCK_WAIT` bounds the wait (default 10 s), and on timeout the aggregator writes nothing, emits `subplan-aggregate-lock-busy` and exits 1. `SUBPLAN_AGGREGATE_LOCK_HELD`, exported by `master-rollup.sh`, names a directory whose lock the caller already holds.
- **Capture-freeze reader.** The reader in `backlog-index` counts a STANDALONE note with `release_class: post-release` as aimed at the next patch release, so it no longer holds an open row. STANDALONE notes of class `docs`, `local-release` and `public-release` stay open.
- **Checkpoint prompt recovery.** The exit-2 text of `stop-checkpoint-check.sh` gains one sentence: the answer is recorded only when the slug leaves `--pending`; otherwise the library lock was busy, and the same `--answer` command is run once more.
- **Corrupt review queue.** `memory-review-banner.sh` prints one banner line naming a review-queue file that is not valid JSON and its repair, instead of a silent zero count.
- **Drift detector.** `sanctioned-schema-drift-detect` treats a live schema whose sha256 equals the installed manifest's recorded sha as the shipped form, not drift. Its DRIFT and PASS lines mention the installed-manifest check only when a record was consulted.
- **Spec-authority banner.** An unarmed prompt no longer injects a plan banner; the `hooks/spec-context-inject.sh` header states the gate the code enforces, a mid-session arming only. An armed plan gets the `SPEC AUTHORITY` banner only while its status is `in-progress`; any other status, an empty one included, gets none.
- **Chronicle and close receipts.** The episodic chronicle row takes its Next-session line from the newest session block of the plan's handoff only (`hooks/session-episode-write.sh`). Session close reports a refused `tasks.md` heal as a skip, checks its receipt write, and reports an unreadable touched-files registry (`skills/librarian/capabilities/session-close.sh`).
- **Overlay loader.** It fails closed on a merge-strategy (union) registry that exists but cannot be read (`hooks/lib/foundation-overlay-load.sh`); the overlay writer warns on it.
- **Smaller changes.** `overlay-master-mutate.sh` defaults `--proposed-by` to `user-direct`; `/govern` project registration refuses an anchor whose directory name holds a control character; `rules-hygiene` reads its whole argument list before it applies the mode rules; the touched-files snapshot reaches `session-deregister.sh` as `--touched-files`; the instructions-loaded log rotates once it reaches a size bound, and one shared reader serves `context-budget-index`, `rules-hygiene --check-load` and the log tools; `matrix-render` and `tasks-render` quote titles in their YAML output; the inbox-triage context now names `redecide-idea.sh`; and the plans governance file now names `librarian:backlog-index` as the holder of the backlog's derived-row rules R-29 to R-31.
- **A delayed dispatch of four hours or more runs once.** `dispatch.sh --plan` or `--job` with such a delay schedules a launchd job whose calendar has no year, so it used to fire again on the same date every year until you ran `--cancel`. The job now runs once, late if the Mac was asleep, and never on a later year's date. It hands the fired run the time it was scheduled for; that run proceeds when the time is now or less than 7 days past, then removes its plist, its loaded label and its pending row. A fire before that time, or 7 or more days after it, runs nothing and cleans up. A one-shot job scheduled before the upgrade keeps the old calendar and can still fire again each year: `--cancel` it and dispatch again. `--cancel` of a job that has not fired works as before, and so does a delay under four hours.
- **Plans-root dead-switch.** `hooks/lib/paths.sh` gains a dead-switch. When `PLANS_DIR_DEAD` or `HOOKS_STATE_OVERRIDE` is non-empty, and the plans root is the one `paths.sh` defaulted to `<account home>/.claude-plans`, the root is re-pointed to an uncreated throwaway path (`<anchor>/.paths-dead-plans.<pid>`). A root you set, a manifest root that points elsewhere, and a HOME jailed to a sandbox are left alone. If you export `HOOKS_STATE_OVERRIDE` for your own hook testing, hooks resolve that throwaway path, not your plans corpus. `hooks/post-handoff-refresh.sh` and `hooks/post-manifest-binder-refresh.sh` now source `paths.sh` (guarded), so they resolve the plans root through the same resolver as every other hook.
- **Uninstall and settings.** `uninstall.sh` keeps `settings.local.json` always, since it holds your permissions and tokens and the installer never writes it. It removes `settings.json` only when its sha256 matches the one recorded at install or upgrade; otherwise it keeps it and prints a message naming it, and `--force-rm-edited` removes an edited `settings.json` anyway. A kept `settings.json` can still list hooks whose scripts the uninstall removed. The pre-uninstall backup copy of `settings.local.json` masks token-shaped `permissions.allow[]` entries. Uninstall boots out and removes only the launchd jobs and plists rendered for this `CLAUDE_HOME`; jobs owned by another home are left alone. One limit: install and upgrade merge the template with your settings, so an edit made before the last install or upgrade is part of the recorded sha, that `settings.json` reads as unedited and is removed (the backup keeps a verbatim copy).
- **What is gated, stated accurately.** The README, orchestrator text and `SECURITY.md` now state what is gated and what an upgrade preserves as the product does it; no behaviour changed. Human gates exist on one path only: a plan run through `dispatch.sh --plan`, or a plan entry of a `--batch` file, reaches `plan-runner.sh`, which stops at every HITL task (one marked irreversible, or any task of a sub-plan whose manifest enables `live_mutation_scope`) and proposes then proceeds for HOTL tasks. Direct `--job` and `--cron` runs, the other `--batch` entries and scheduled wrappers carry no human gate. `.gitignore` is merged on every install or upgrade, and `governance/overlay-master.json` on an upgrade that finds a recorded installed baseline. On an upgrade whose lane is verified and whose recorded installed baseline is byte-identical to the live foundation manifest, the edited-file check skips `governance/overlay-master.json`, so it does not stop the upgrade, and files under `migrations/` can be replaced without a sidecar; this qualifies the v1.19.0 sentence that said the upgrade "never stops on them".

## Upgrading

- **Run the upgrade as usual**: `install.sh --upgrade --apply`, typed in a plain terminal.
- **Confirm the migration ran.** After the upgrade, confirm this release's own migration is recorded; a bumped `foundation_version` alone is not proof:

  ```bash
  jq -r '.migrations_applied[]' "$CLAUDE_HOME/governance/.installed-state.json"
  ```

  The list must include `0013-inbox-deferred-converge`. If it is missing, run `install.sh --upgrade --apply` once more; the runner selects any migration whose id is not yet listed.
- **If you had inbox notes marked `DEFERRED`**, expect each to be rewritten to `NO-BUILD` with a `<slug>.md.pre-0013` recovery copy beside it. Delete the copies when you no longer need them.
- **If you have untriaged inbox notes**, run `/backlog-triage` on them before you graduate them.
- **Expect permission prompts where advisories used to pass.** A write that draws an advisory now goes through your normal permission flow.
- **If you turned a required hook off**, it now stays off across upgrades; `field-set.sh settings hook on <hook>` restores it.
- **If you run library promotion**, run `library-scrub.sh --triage <plan>` for each plan that `library-scrub.sh --pending` still lists with an old failure reason. Your Claude Code CLI must be 2.1.169 or later.

## Known issues

- **Bash writes skip the write guard.** The guard that checks file writes runs on the Write and Edit tools only. A write made through a shell command (a redirect, a heredoc, an interpreter) is not checked by it.
- **The document-amender's model call also gets the destination's current text.** When the document-amender asks the model for an amendment, the request carries the current text of the destination file as well as the prompt asset.
- **A second upgrade can replace an earlier `.foundation-local` copy.** If you edit a file, an upgrade saves your copy as `<file>.foundation-local`, and you edit the file again without reconciling that copy, the next upgrade overwrites the earlier copy. Reconcile or move a `.foundation-local` copy before you upgrade again.
- **`--force-all` replaces files without a backup.** On an install with no installed record, `--force-all` overwrites edited files with no sidecar copy and no backup of them. Keep your own copy of anything you edited first.
- **Hand edits in generated index regions are regenerated.** The regions of an index file that a generator owns are rewritten on its next run; an edit you make inside one does not survive.

A fix for each is planned.
